About

This project automates semester timetable generation for GIK Institute's Spring 2026 catalogue. It models scheduling as a Constraint Satisfaction Problem and solves it with a greedy CSP solver: each course session is assigned to a feasible (day, time, room) tuple while a rule-based constraint checker enforces hard constraints such as teacher, room, and section conflicts using O(1) hash-map lookups. On top of the hard constraints, soft objectives — day-load balancing, consecutive-slot penalties, and capacity-aware room fallback — shape the result toward a well-balanced, realistic weekly grid (Mon–Fri) that mirrors the institution's official timetable layout.

Features

🗓️ Weekly Recurring Grid Builds a single Mon–Fri schedule that every teaching week of the semester follows.
🧩 Greedy CSP Solver Rule-based constraint checking assigns sessions into feasible day/time/room slots.
🚫 Conflict Prevention Blocks teacher, room, and section double-bookings automatically.
🔒 Room Locking Multi-session courses stay anchored to a single, consistent room.
📄 PDF-Aware Slot Rules Reproduces institutional quirks, including the shifted Friday morning grid.
🖥️ Dual Workflow CustomTkinter GUI for one-click generation, plus a CLI for headless batch runs.
📊 Excel Export Outputs a room × slot grid grouped by building, color-coded by department.
📈 Stats View Per-day and per-building load statistics surfaced right in the GUI.

Constraint Model

Hard constraints (always enforced)

  • No teacher double-booked
  • No room double-booked
  • No section taught twice on the same day
  • All sessions of a course share one locked room

Soft objectives (optimized when possible)

  • Day-load balancing, with Friday seeded lighter
  • Penalty for 3 consecutive slots on one instructor
  • Capacity-aware room allocation with fallback
  • Last-resort virtual/TBA lab fallback
